## Использование в проекте


**Где вызывается.** Отзыв поступает в систему через `POST /reviews`. Система передаёт текст модели по API и получает метку (`label`) и уверенность (`score`). Они сохраняются в `ReviewClassification` как `tone` и `confidence` и возвращаются в ответе.

**Как используется результат.**
- Тональность каждого отзыва видит производитель, а интернет-магазин получает её для показа покупателям.
- По сохранённым тональностям `POST /analysis` считает среднее: негативный отзыв = 0, нейтральный = 1, позитивный = 2. Параметр `include_neutral` определяет, учитывать ли нейтральные отзывы.


## Входные данные

Вход - строка

example:
"Привет, ты мне нравишься!"

## Выходные данные

Возвращает метку и то, насколько модель уверена в ответе.

example:
[{'label': 'positive', 'score': 0.9818321466445923}]

## Ограничения

Автор не публиковал раздел об ограничениях, но постараюсь описать очевидные.

1. Длина входа ограничена 256 токенами.
2. Потенциальное ограничение для нашего проекта: Сленги и эмодзи скорее всего не будут правильно интерпретированы, часто будет ошибаться на сарказме.
3. Модель обучена не на отзывах о товарах.
4. Одна метка на весь текст -> смешанные отзывы ("Товар хороший, доставка плохая") упростятся.

## Не рекомендуется использовать

- Для текстов не на русском языке или с эмодзи.
- Для выявления накрутки и фейковых отзывов.
- Для длинных отзывов, так как модель обрежет отзыв длиннее 256 токенов.
