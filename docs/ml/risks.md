# Риски и ограничения

## Потенциальный bias

### Риск 1. Смещение по предметной области (домен)

**Риск:**  
Модель обучена на объединении пяти наборов: новостные тексты, пользовательские тексты и отзывы. Единственный набор отзывов о товарах (RuReviews) собран по одной категории, «Женская одежда и аксессуары». Существует потенциальный риск, что на отзывах других категорий (например, электроника с техническим жаргоном) качество классификации будет иным, чем заявленное. Метрики на странице модели приведены для всей смеси наборов, по отдельным наборам и категориям данных нет, поэтому доступной информации недостаточно для оценки разницы.

**Возможное последствие:**  
Для товаров некоторых категорий тональность отзывов может определяться менее точно. Тогда средняя тональность в `POST /analysis` будет искажена для этих товаров, а производитель или покупатель увидит менее надёжную оценку.

**Что можно сделать:**  
Перед использованием проверить модель на небольшой собственной размеченной выборке отзывов и сравнить F1-меру по категориям товаров. Если качество по какой-то категории заметно ниже, ввести для неё более строгий порог уверенности (отзывы ниже порога получают `status: failed` и уходят на ручную проверку) или рассмотреть дообучение.

### Риск 2. Смещение разметки, полученной из звёздных оценок

**Риск:**  
Метки в наборе RuReviews получены автоматически из пользовательских звёзд, а не из анализа текста. Отзывы собирались по популярным товарам с высоким средним рейтингом, а авторы набора отмечают, что одинаковые тексты встречались с разными оценками. Существует потенциальный риск, что модель частично усвоила связь «звёзды → тональность», а не «содержание → тональность». Это особенно важно для нашего проекта, который исходит из того, что звёздные рейтинги могут быть ненадёжны. Насколько это влияет на итоговые ответы модели, необходимо проверить, доступной информации для вывода недостаточно.

**Возможное последствие:**  
Модель может системно ошибаться на отзывах, где текст и оценка расходятся (например, нейтральный текст с высокой оценкой, или краткие отзывы вроде «норм»). Так как нейтральный отзыв в расчёте равен 1, такие ошибки сдвигают среднюю тональность.

**Что можно сделать:**  
Вручную разметить выборку отзывов (по тексту, без учёта звёзд) и сравнить ответы модели с человеческой разметкой, отдельно посмотрев ошибки на нейтральном классе. Результаты записать в Model Card. В работе системы использовать порог уверенности и список неклассифицированных отзывов для ручной проверки.

## Этические риски

### Риск 1. Неправильная автоматическая классификация отзывов

**Риск:**  
Модель может ошибиться в тональности отзыва, особенно на нейтральном классе (f1-score 0,73 против 0,84 у позитивного), на сарказме, смешанных оценках и коротких отзывах. Нейтральный отзыв в расчёте равен 1, поэтому ошибки между классами сдвигают среднюю тональность.

**Последствие:**  
Производитель может сделать неверный вывод о восприятии товара, а покупатель увидит искажённую оценку. Это может повлиять на репутацию товара и на решения о покупке.

**Способ снижения риска:**  
Использовать порог уверенности: отзывы с низкой уверенностью получают `status: failed`, не участвуют в расчёте и попадают в список для ручной проверки. Возвращать вместе со средним распределение по тональностям и количество учтённых отзывов, чтобы результат можно было проверить. Если данных мало, возвращать «Недостаточно данных для расчёта» вместо ненадёжного среднего. Перед использованием проверить качество модели на собственной размеченной выборке.

### Риск 2. Обработка персональных данных в текстах отзывов

**Риск:**  
Текст отзыва может содержать персональные данные автора (имя, телефон, адрес, номер заказа). Кроме текста, в запросе передаётся `author_id`. Тексты передаются ML-модели, и необходимо уточнить, где она размещена и кто имеет доступ к передаваемым данным. Доступной информации для оценки этого недостаточно.

**Последствие:**  
Персональные данные могут быть сохранены или переданы без ведома автора, что создаёт риск нарушения требований законодательства о персональных данных и потери доверия пользователей.

**Способ снижения риска:**  
Передавать модели только текст отзыва, без `author_id` и иных идентификаторов. При возможности удалять из текста телефоны, адреса электронной почты и другие явные персональные данные до передачи модели. Хранить результаты в базе заказчика, как предусмотрено проектом, и не сохранять лишние данные в самой системе. Перед запуском проверить применимые требования закона.


## Что остаётся неизвестным

Доступной информации недостаточно, чтобы оценить, различается ли качество модели для разных групп авторов (стиль письма, региональная лексика, длина отзывов). Для этого нужны данные об авторах или специальная проверка, поэтому утверждать наличие или отсутствие такого смещения нельзя.
