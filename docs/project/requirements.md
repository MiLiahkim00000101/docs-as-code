# User Story 1

Как производитель товара,
я хочу видеть распределение отзывов по тональности (сколько негативных, нейтральных и позитивных) и список отзывов, которые не удалось классифицировать,
чтобы понимать, из чего складывается средняя оценка, и вручную проверить спорные отзывы.

Критерии приемки:

- после обработки система отображает количество и долю негативных, нейтральных и позитивных отзывов;
- система отдельно показывает список отзывов, которые не удалось классифицировать, с текстом каждого отзыва;
- отзывы, не вошедшие в классификацию, не учитываются при расчёте средней тональности;
- производитель может отфильтровать список отзывов по тональности;
- если отзывов для отображения нет, пользователь получает сообщение «Нет данных для отображения».

# User Story 2

Как интернет-магазин,
я хочу дать пользователям возможность видеть общую картину отзывов о товарах на основе содержаний сообщений, а не только звезды, которые могут быть накручены пустыми отзывами,
чтобы дать пользователям магазина видеть честную картину отзывов на товар

Критерий приемки:

- система принимает текст отзыва/ов;
- после обработки отображается категория/средние по всем отзывам. В случае среднего можно будет указать, учитывать ли вес нейтральных отзывов. Если да, то негативный отзыв считать за 0, позитивный за 2, а нейтральный за 1, считать как среднее арифметическое. Если нет, то необходимо делать то же самое, только нейтральный не учитывать при подсчете среднего арифметического; В случае отсутствия позитивных и негативных отзывов, считать среднее как 0.
- Если классификация невозможна, пользователь получит сообщение об ошибке

# User Story 3

Как покупатель интернет-магазина,
я хочу видеть на странице товара оценку, рассчитанную по содержанию отзывов, и долю позитивных, нейтральных и негативных отзывов,
чтобы принять решение о покупке на основе реального мнения других покупателей, а не только звёздного рейтинга.

Критерии приемки:

- на странице товара отображается средняя тональность отзывов рядом со звёздным рейтингом;
- отображается доля позитивных, нейтральных и негативных отзывов в процентах;
- отзывы, которые не удалось классифицировать, не учитываются в расчёте;
- если для расчёта недостаточно отзывов, вместо оценки отображается сообщение «Недостаточно данных для расчёта»;
- оценка обновляется после добавления нового отзыва.


# UC-01 Анализ тональности отзывов о товаре

Актор: Производитель или поставщик товара

Цель: получить среднюю тональность отзывово о товаре

Предусловие: по товару есть один или несколько текстовых отзывов

Основной сценарий:

1. Производитель загружает отзывы о товаре.
2. Производитель выбирает способ расчёта: учитывать нейтральные отзывы или нет.
3. Система передаёт тексты отзывов ML-модели по API.
4. ML-модель определяет тональность каждого отзыва (негативная, нейтральная, позитивная).
5. Система выполняет UC-04 (расчёт средней тональности).
6. Система отображает тональность каждого отзыва и среднюю тональность по товару.

Альтернативный сценарий:

4а. Модель не может классифицировать отзыв: он помечается «не классифицирован», исключается из расчёта и остаётся доступным для ручной проверки.

5а. UC-04 вернул «Недостаточно данных для расчёта»: система показывает это сообщение вместо средней тональности.

Результат: производитель видит среднюю тональность отзывов и список неклассифицированных отзывов.
